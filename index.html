Abstract

Medical vision-language models (VLMs) show promise for clinical image understanding, but their computational and memory requirements hinder deployment on resource-constrained clinical hardware. Post-training quantization (PTQ) offers a practical compression strategy without retraining, yet its effectiveness depends strongly on the calibration data.

We propose CoreCalib, a training-free and quantizer-agnostic framework for constructing compact calibration sets that preserve the target medical VQA distribution. CoreCalib stratifies data by clinical question class, identifies representative visual modes using frozen DINOv2 features with UMAP and HDBSCAN, and expands selected images into class-balanced question-answer pairs.

On Kvasir-VQA-x1, we evaluate CoreCalib with MASQuant, GPTQ, and QIG using a fixed 128-pair budget. CoreCalib achieves the best METEOR with all three quantizers and the best ROUGE-L with MASQuant and GPTQ. With W4A8 MASQuant, it improves METEOR from 0.5672 with COCO calibration to 0.6234, recovering approximately 41% of the degradation relative to BF16. These results support CoreCalib as a data-centric component for resource-efficient medical VLM deployment.

Why calibration data matters

Multimodal PTQ methods usually calibrate on a small, generic COCO image-caption set, even when the model has been fine-tuned on a very different clinical distribution. In medical VQA, a calibration example is not just an image: the same endoscopic frame can be asked about abnormality presence, polyp type, instrument count, anatomical landmarks or image quality. A calibration set can therefore look visually representative and still miss the clinical tasks the model must perform, or it can cover frequent question classes while spending its small visual budget on atypical images.

Simply switching to random in-domain data is not enough either. Under W4A8 MASQuant, a random in-domain calibration set still leaves a 0.0870 METEOR drop relative to the half-precision model. We therefore treat calibration as a multimodal workload-construction problem: under a tiny budget, the set should jointly represent the visual distribution and the clinical question distribution.

Method

Given a medical VQA training set D = {(I, q, a, c)} with images, questions, answers and clinical question classes, CoreCalib constructs a calibration set S = F(D, N) with |S| = N. The construction F is independent of the internal objective of the PTQ algorithm, so the resulting set is passed unchanged to any quantizer. CoreCalib makes three decisions that are usually conflated:

Stage 1

Question-class stratification

The 18 clinical question classes of Kvasir-VQA-x1 are used as strata. Strata overlap at the image level, so one representative image can serve several question types.

Stage 2

Density-aware visual core discovery

Within each class, images are embedded with a frozen DINOv2 encoder, reduced with UMAP and clustered with HDBSCAN. Following CoDA, each cluster contributes the real image with the highest membership probability, and post-processing yields exactly K representatives.

Stage 3

QA expansion and class-balanced sampling

Representatives are expanded into all of their QA pairs, and the budget is filled round-robin across classes, so frequent classes cannot consume it. With N = 128, this yields 128 QA pairs from only 23 unique images.

We use density-based discovery rather than centroid-based clustering because the budget is small and medical image manifolds can contain non-convex, unevenly populated modes. A K-Means centroid can be geometrically central without corresponding to a representative real image, whereas HDBSCAN retrieves real images from the dense core of each mode.

Results

We quantized Qwen3.5-4B fine-tuned on Kvasir-VQA-x1 with three PTQ methods and evaluated on the full test split (15,955 samples). Every calibration strategy used exactly 128 samples: COCO (ShareGPT4V image-caption pairs, the common generic choice), Random (random images with the same QA expansion and balancing), and K-Means (per-class K-Means on the same DINOv2 features, nearest real image to each centroid). Generic COCO calibration caused the largest degradation, and every in-domain strategy recovered a substantial part of it, most notably with MASQuant, where CoreCalib improved METEOR by 0.0562 over COCO. CoreCalib achieved the best METEOR with every quantizer and the best ROUGE-L with MASQuant and GPTQ. GPTQ and QIG were less sensitive to the calibration data, which is consistent with how each quantizer uses its calibration inputs: MASQuant and QIG estimate activation statistics, smoothing factors or token-level sensitivities from them, while GPTQ mainly estimates reconstruction statistics.

Qualitative examples

Replacing density-based discovery with Random or K-Means selection reduced ROUGE-L and METEOR, so the gain is not explained by the DINOv2 feature space alone. Removing question-class stratification also lowered performance, which supports covering heterogeneous clinical tasks explicitly. Using the second-most-confident cluster member raised BLEU but lowered ROUGE-L and METEOR, suggesting that images closest to the density core are preferable. For the budget, BLEU and ROUGE-L grew from 32 to 256 samples while METEOR was non-monotonic: a larger calibration set does not guarantee uniformly better capability retention.

Setup

  • Model: Qwen3.5-4B fine-tuned on Kvasir-VQA-x1 with QLoRA (rank 16, α = 32), released as Medico2026-unsloth-Qwen3.5-4B-QLoRA-SFT.
  • Quantizers: MASQuant (W4A8), GPTQ (W4A16, group size 128), QIG (W4A8), all with their official implementations.
  • CoreCalib: DINOv2 ViT-B/14 features; UMAP with 50 neighbors, 50 dimensions, min. distance 0; HDBSCAN with min. cluster size 25 and 3 min. samples; K = 10 representatives per class.
  • Data: Kvasir-VQA-x1, 159,549 QA pairs on 6,500 GI endoscopy images and 18 question classes. Calibration used the training split only; evaluation used the full test split.
  • Hardware: NVIDIA A100 40GB GPUs.
